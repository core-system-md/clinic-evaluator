# ADR-004 — هوية الإدارة وصلاحيات Owner/Admin

**الحالة:** Accepted

## القرار

اعتماد **Option B — جدول إداري مستقل** مرتبط بـSupabase Auth.

يكون:
- `owner`: حساب إداري رئيسي واحد فقط، مالك النظام، بصلاحيات كاملة.
- `admin`: إداريون حقيقيون بصلاحيات تشغيلية، ولا يملكون صلاحية إنشاء Owner آخر أو تغيير ملكية النظام.

يكون جدول `admin_users` هو المصدر الرسمي للحقيقة للتفويض الإداري، بينما Supabase Auth هو مصدر هوية المستخدم.

سيُصمم الجدول بحيث يمكن إضافة permissions تفصيلية لاحقاً دون تغيير نموذج الهوية.

## قواعد أمنية

- لا تعتمد الصلاحيات على `localStorage` أو عناصر واجهة مخفية/ظاهرة.
- لا تستخدم `user_metadata` لاتخاذ قرارات التفويض.
- أي `SECURITY DEFINER` لازمة للتحقق ستكون محدودة ومحصنة وليست بوابة CRUD عامة.
- لا يصل أي secret أو service key إلى المتصفح.
- إلغاء صلاحية الإداري يتم من مصدر مركزي واضح.

## نطاق التنفيذ

هذا القرار يحدد المعمارية فقط. لن يتم استبدال نظام الإدارة الحالي في الإنتاج قبل اكتمال تدقيق P0، وإنشاء المخطط الموثق لقاعدة البيانات، وتصميم مسار ترحيل واختبارات رجوع آمنة.

**يكمل ADR-001 وADR-002 وADR-003.**
