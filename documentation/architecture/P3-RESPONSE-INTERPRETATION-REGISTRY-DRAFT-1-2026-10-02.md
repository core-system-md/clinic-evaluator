## 1. Source-of-truth rule

This registry does not replace current Supabase option identity or visible text.

For each entry:

`option identity = assessment slug + question code + option index`

The live Supabase `options.id` UUID remains the immutable source identity. `option_value` is preserved as historical/source data and is not the authoritative meaning.

The registry is derived from:
- current Supabase question/option rows (read-only verification);
- `P3-QUESTION-BY-QUESTION-SEMANTIC-SCORING-SPEC-DRAFT-1-2026-10-01.md`;
- `P3-CONSTRUCT-COMPONENT-MAP-DRAFT-1-2026-10-02.md`;
- `P3-RESPONSE-INTERPRETATION-CONTRACT-DRAFT-1-2026-10-02.md`;
- `P3-OWNER-METHODOLOGY-DECISIONS-2026-10-02.md`;
- `P3-OWNER-METHODOLOGY-AMENDMENT-2026-10-02.md`.

## 2. Field contract

Each option is interpreted as:

`question#option_index | semantic_state_key | measurement_type | component | layer | direction | score_mode | anchor | eligible | criticality | consistency_role | evidence_role | context_required`

Allowed values follow the Response Interpretation Contract.

**Important:** a shared anchor such as 40 or 100 does not imply identical meaning across questions.

## 8. Explicit semantic exceptions

1. **Option count is never a scoring rule.**
2. **Missing is not zero.**
3. **Context-dependent responses are not ordinal by position.**
4. **Evidence/measurement claims do not become observed outcomes.**
5. **Digital maturity does not become clinical outcome.**
6. **Criticality is independent from numeric anchor.**
7. **Trap metadata is not an automatic penalty.**
8. **Q2c9f29 option 2** has source value 0 but a confirmed corrective interpretation of 40 for the next controlled assessment/scoring version; production remains unchanged.
9. **Patient Journey Q7** is semantic-only pending construct/measurement validation; its three options are not automatically treated as 0/40/100.
10. **Clinic Q4/Q5/Q6** retain source pattern 0/0/40/100/100.
11. **Medical four-option contextual states** remain separate from numeric ranking.
