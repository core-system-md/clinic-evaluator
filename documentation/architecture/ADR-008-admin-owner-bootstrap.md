# ADR-008 — تعيين هوية مالك النظام

**الحالة:** Architectural Decision Required

## السبب

ADR-004 يعتمد Supabase Auth للهوية و`admin_users` كمصدر الحقيقة للصلاحيات، مع مالك أساسي واحد لا يمكن إنشاء مالك ثانٍ أو نقل الملكية عبر واجهة الإدارة.

تم تنفيذ طبقة `admin_users` مع RLS وقيود singleton للمالك، لكن قاعدة البيانات الحالية تحتوي على مستخدمي Supabase Auth ولا تحتوي على أي سجل إداري بعد.

## القرار المطلوب من مالك المشروع

يجب تحديد مستخدم Supabase Auth الذي يمثل **مالك النظام الأساسي**، ثم تتم تهيئة سجل واحد له في `admin_users` بدور `owner`.

لا يجوز للهندسة اختيار الحساب تلقائيًا أو اعتبار أول مستخدم هو المالك، لأن ذلك يحول قرار ملكية النظام إلى افتراض أمني.

## ما تم تنفيذه

- جدول `admin_users` مرتبط بـ`auth.users`.
- الدوران المسموحان: `owner` و`admin`.
- قيد فريد يمنع أكثر من مالك واحد.
- RLS مفعّل.
- إنشاء المديرين الجدد مسموح للمالك فقط.
- تحديث/حذف سجلات المديرين delegated admins مقيّد بالمالك.
- لا توجد سجلات إدارية حاليًا.

## حدود هذه المرحلة

لن يتم استبدال شاشة الإدارة القديمة أو تشديد صلاحيات جداول الإدارة بشكل نهائي قبل تعيين المالك، حتى لا يتم نقل النظام إلى حالة لا يوجد فيها حساب إداري موثوق.
