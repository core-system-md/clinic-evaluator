# ADR-002 — مصدر الحقيقة لنتيجة التقييم

**الحالة:** Accepted — Amended by ADR-007  
**التعديل:** 2026-10-01

## القرار الحالي

اعتماد **Server-authoritative scoring only**.

المتصفح لا يحسب النتيجة الرسمية ولا يستلم قواعد scoring الخاصة بالتقييم. يرسل الإجابات الأصلية فقط إلى خدمة التقييم الخادمية، ويعيد الخادم النتيجة الرسمية بعد إعادة بناء القواعد من المصدر الخادمي.

## تعديل ADR-002 السابق

كان القرار السابق يعتمد **Hybrid / Server-authoritative scoring** بحيث يحسب المتصفح نتيجة فورية ثم يعيد الخادم الحساب الرسمي.

بموجب ADR-007، أُلغي الجزء الخاص بالحساب الفوري داخل المتصفح لأن ذلك يتعارض مع القرار المعتمد في ADR-005 الذي يعتبر أوزان الإجابات، قواعد الـTraps، خرائط KPI/EV ومنهجية الحساب بيانات خاصة لا تُسلّم للعميل.

## الشكل المستهدف

المستخدم
→ الإجابات الأصلية
→ خدمة التقييم الخادمية
→ محرك التقييم الخادمي
→ النتيجة الرسمية
→ قاعدة البيانات
→ تقرير المستخدم

المتصفح يعرض النتيجة التي يعيدها الخادم فقط.

## قواعد ملزمة

1. لا تُرسل الدرجة النهائية من المتصفح كمصدر حقيقة.
2. لا تُرسل قواعد scoring السرية إلى JavaScript أو JSON العام.
3. الخادم يعيد بناء scoring configuration من قاعدة البيانات.
4. الإكمال والحفظ والاستهلاك تتم عبر مسار خادمي ذري.
5. إعادة إرسال الإكمال لنفس الجلسة يجب أن تكون idempotent.
6. زمن الاستجابة جزء من التحقق التشغيلي، لكنه لا يبرر إعادة كشف القواعد السرية.

## سبب التعديل

ثبت أثناء التنفيذ أن متطلبَي:
- الحساب المحلي الفوري،
- وإخفاء منهجية الحساب عن العميل،

لا يمكن تحقيقهما معًا حرفيًا في متصفح غير موثوق.

لذلك تم تعديل القرار صراحةً بدل تجاوزه ضمنيًا، وفق ADR-007.

## ملاحظات

الدالة القديمة `calculate_session_score(uuid)` لا تُعتمد كمصدر للحقيقة لأنها مبنية على مقياس 1–5 بينما نموذج التقييم الحالي يعتمد 0/40/100.

المحرك الأصلي `engine/engine.js` يبقى مرجع parity أثناء الانتقال، وليس محرك تشغيل للعميل.

**يرتبط هذا القرار بـ ADR-001 وADR-005 وADR-006 وADR-007.**
