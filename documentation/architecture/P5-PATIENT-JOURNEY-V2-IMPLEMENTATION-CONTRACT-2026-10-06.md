## 3. Critical implementation finding that must be corrected

The current scorer module `p3-scorer-v1.mts` imports only:

`p3-response-interpretation-registry-v1.json`

Although `p3-production-adapter.mts` separately loads the v2 registry and places v2 interpretation entries into the configuration digest, `scoreP3IntegratedV1()` currently calls:

`scoreP3AssessmentV1({ assessmentSlug, selections })`

without passing an interpretation version.

Therefore `scoreP3AssessmentV1()` defaults to:

`interpretationVersion = 1`

This creates a provenance/behavior risk for any version-2 assessment: the digest can contain v2 configuration while actual option interpretation remains version 1.

### Required implementation correction

The implementation must:

1. Make interpretation version an explicit input to the integrated scoring path.
2. Route version 2 assessments to the v2 interpretation registry.
3. Preserve version 1 behavior for version 1 assessments.
4. Store the actual interpretation version used in structured provenance.
5. Ensure the configuration digest covers the exact interpretation configuration actually used.

This is a **code-path integrity requirement**, not a content redesign.

[
AxisScore_A =
\frac{\sum_{i \in eligible(A)} (anchorScore_i / anchorMax_i)\times100}

| TCI | CONVERSION .30 / SCHEDULING .40 / ADMIN .30 | 0.30 |

### 12.4 KPI calculation rule

The current P3 engine:

- never imputes missing roles;
- uses only numerically measured mapped roles;
- normalizes over contributing declared weights;
- marks full coverage as `available`;
- marks incomplete but calculable coverage as `partial`;
- marks zero measured mapped roles as `unavailable`;
- exposes a `coverage` value.

For Patient Journey v2, this means the current mappings produce **partial projections**, not fully covered KPI measurements.

This is acceptable for the implementation checkpoint because the engine already preserves the distinction.

### 12.5 KPI reporting guardrail

The report layer must never present a partial KPI as if it were a full KPI measurement.

Every surfaced partial KPI must retain:

- KPI code;
- numeric value;
- status = `partial`;
- coverage;
- input role provenance.

No missing role may appear as 0.

No KPI may alter the core Patient Journey score.

A future redesign of KPI mappings or a mandatory-role/minimum-coverage policy is a separate methodology decision and is not silently introduced here.
