# ADR-003 — مصدر الحقيقة لمخطط قاعدة البيانات

**الحالة:** Accepted

## القرار

اعتماد **Option B — جعل Git مصدر الحقيقة لمخطط قاعدة البيانات**، مع تجهيز المشروع للانتقال إلى بيئة اختبار مستقلة لاحقاً دون إعادة تصميم المسار.

سيتم إنشاء baseline للمخطط الحالي بعد مراجعته وتنظيفه، ثم تصبح التغييرات المستقبلية على قاعدة البيانات versioned migrations محفوظة في Git.

## قواعد التنفيذ

1. لا نحول الحالة الحالية إلى baseline بشكل أعمى؛ تتم مراجعة الجداول والسياسات والدوال والـgrants قبل تثبيت baseline.
2. لا تُعتبر تعديلات Dashboard اليدوية مساراً مقصوداً للتغيير بعد اعتماد baseline.
3. كل تغيير schema/RLS/function/grant لاحق يُمثل كتغيير versioned.
4. لا يتم إجراء تغييرات إنتاجية حساسة أثناء إنشاء baseline إلا بعد التحقق من أثرها.
5. عندما تتوفر بيئة staging مناسبة، تُستخدم للتحقق قبل الإنتاج.

## السبب

المشروع الحي يحتوي بنية تشغيلية فعلية بينما مستودع Git لا يحتوي مسار migrations حالياً. اعتماد Git كمصدر الحقيقة يمنح المشروع قابلية المراجعة وإعادة البناء والتتبع، ويمنع استمرار انجراف قاعدة البيانات بعيداً عن الكود.

Supabase توصي باستخدام migrations versioned في المستودع للحفاظ على اتساق المخطط بين البيئات.

**هذا القرار يكمل ADR-001 وADR-002.**
